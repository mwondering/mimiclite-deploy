# SONIC release: GR00T PICO adaptation

Chinese: [README_zh.md](README_zh.md).

This package adapts the default SONIC release used by the local
`GR00T-WholeBodyControl` checkout at commit
`087f9ac01d46f6d8e4d0b73c01ae64799f292a38`. Its PICO full-body **POSE** mode
uses the SMPL encoder. The optional G1 encoder instead consumes retargeted robot
motion. This is the default release, not the low-latency or v1.1 checkpoint.

The checkout contained source and configuration but no SONIC weights. The source
project's official `nvidia/GEAR-SONIC` encoder/decoder were downloaded at pinned
revision `6733128a3d8a523b1418b06bca3cdf61c8b0987f`. The original learned graphs
and finite scalar quantization are retained, with a fixed mode and zero-filled
inactive inputs, inside one ONNX per mode. Each adjacent `policy.json` records
source hashes, layouts, model hash, and numerical parity. Source/model license
notices are included in [LICENSE](LICENSE).

| Mode | YAML | Model inputs | Model outputs |
| --- | --- | --- | --- |
| PICO full-body SMPL | `smpl/policy.yaml` | `smpl_input[840]`, `proprioception[930]` | `action[29]`, `token[64]` |
| G1 robot reference | `g1/policy.yaml` | `g1_input[640]`, `proprioception[930]` | `action[29]`, `token[64]` |

External inputs/outputs are unbatched to match this runtime. The graphs insert
and remove the source batch dimension internally. IR 7 / opset 13 are preserved;
CPU ORT 1.23.2 was tested locally. GPU/onboard execution has not been tested.

## Run PICO in simulation

Run these commands from the `mimiclite-deploy` root in separate terminals.
Restart an existing publisher with `--publish-smpl` enabled:

```bash
HF_HUB_OFFLINE=1 HF_HUB_DISABLE_TELEMETRY=1 \
uv run --project venv/pico sim2real/teleop/pico_retarget_pub.py \
  --robot g1 --actual-human-height 1.76 --publish-hz 30 --publish-smpl
```

Set the human height to your actual height in meters. Start MuJoCo if it is not
already running:

```bash
HF_HUB_OFFLINE=1 HF_HUB_DISABLE_TELEMETRY=1 \
uv run --no-sync python sim2real/sim_env/base_sim.py --robot g1
```

Stop the previous tracking process before starting this policy:

```bash
HF_HUB_OFFLINE=1 HF_HUB_DISABLE_TELEMETRY=1 SIM2REAL_ORT_NUM_THREADS=1 \
uv run --no-sync python sim2real/rl_policy/tracking.py \
  --robot g1 \
  --policy-config checkpoints/sonic/release/smpl/policy.yaml \
  --inference-backend onnx-cpu \
  --robot-io zmq \
  --motion-backend smpl_zmq \
  --motion-zmq-connect tcp://127.0.0.1:28702 \
  --controller pico \
  --pico-zmq-connect tcp://127.0.0.1:5592 \
  --rl-rate 50
```

Press **A → A+B → X** to initialize, enter policy control, and follow the live
pose. Body streaming and controller streaming must both be enabled on PICO.
The source project's planner, VR three-point modes and button state machine are
not part of this integration; this repository's PICO controls remain in use.

The initial paused SMPL reference uses official skeleton FK with upright root
and arms down. Later `X` pauses hold the last SMPL body pose, wrists and heading.
The publisher's parallel GMR viewer shows a robot reference and returns to its
default stand when paused; it does not display the SMPL policy target directly.

SMPL samples frames `[0..9]` at 50 Hz: 180 ms furthest lookahead plus 40 ms
buffer tolerance = 220 ms reference delay. To use the optional G1 mode, switch
to `g1/policy.yaml`, `--motion-backend zmq`, and port `28701`. G1 samples
`[0,5,10,15,20,25,30,35,40,45]`, so its reference delay is 940 ms.

## Matched source semantics and fixes

- SMPL input order: all 10 × 24 × 3 canonical joint positions, then 10 × 6
  relative root orientations, then 10 × 6 wrist angles. G1 order: all future
  joint positions, all future velocities, then root orientations. The source
  encoder performs its own subsequent reshape/concatenation.
- Proprioception order: angular velocity, joint position minus default,
  joint velocity, previous raw action, projected gravity. Each contains ten
  frames, oldest first. Release YAML opts into the exact C++ startup padding
  and heading formula; existing SONIC defaults remain available to other configs.
- Source C++ missing histories have zero values, including a zero quaternion.
  Its gravity calculation therefore produces +Z for missing frames. This
  unusual behavior was verified against compiled source, not inferred from docs.
- Policy action order, default pose, gains and scales are generated by compiling
  the original `policy_parameters.hpp`; values are recorded in `source_config.json`.
  Actions have no added clip: the source applies `default + scale * action`.
- PICO SMPL wrists now use the source elbow-swing/wrist-rotation mapping instead
  of GMR wrist IK. The ordinary G1 stream keeps its existing retargeted joints.
- The publisher now sends a valid FK-derived SMPL reference during initial
  pause, before the first live frame. Official replay joint labels/order were fixed.
- The SMPL buffer now interpolates positions/wrists linearly and rotations with
  shortest-path SLERP when converting 30 Hz publisher frames to 50 Hz references.

The official FK asset `smpl/human_joints_info.pkl` is copied from
`gear_sonic/data/human/human_joints_info.pkl`, SHA256
`4de0bae69caf31e8829a2d3e8adecd887f29115af60a0b8d59237dfbfea1c975`.
Its native root offset is preserved; the canonical joints are not re-centered.

## Validation: 2026-09-08

- Each mode passed 64 nonzero graph comparisons against original encoder →
  decoder: maximum action and token error **0.0**, deterministic repeats.
- Compiled actual source C++ history/rotation functions matched the deployment
  observations across 25 random state frames. Raw PICO preprocessing also
  matched source code: skeleton error ≤3e-6 m, wrist error ≤8e-8 rad.
- Root test suite: **56 passed, 1 skipped**, plus two artifact subtests passed.
  The skipped publisher test requires GMR; it passed in the teleop environment,
  where the PICO SMPL and hand-grip suite had **11 passing tests**.
- Actual `Tracking.step` replay: 700 steps, 30 Hz SMPL JSON → 50 Hz controller,
  finite inputs/actions, zero command-mapping and wrist-order error. Single-thread
  CPU mean **4.77 ms**, p99 **5.32 ms**, max **5.73 ms**, no step over 20 ms.
  This replay used an in-memory robot I/O sink, without physical feedback.

Integrated MuJoCo validation used seed `20260908`, 50 Hz policy / 200 Hz physics,
robot initialized to reference frame zero, two seconds of active-policy initial
pause, followed by motion playback and final-frame hold:

| Test | Total simulation | Minimum pelvis Z | Maximum tilt | Final XY displacement error | Final hold |
| --- | ---: | ---: | ---: | ---: | ---: |
| SMPL neutral stand | 10 s | 0.785 m | 4.11° | 0.0037 m | 6.02 s |
| SMPL official walk | 44.1 s | 0.726 m | 10.73° | 0.0972 m | 2.09 s |
| G1 paused stand | 10 s | 0.780 m | 0.79° | 0.0009 m | 6.02 s |
| G1 official walk | 44.1 s | 0.728 m | 10.42° | 0.1177 m | 2.09 s |

All runs completed without falling. The paired official walk has 2002 frames at
50 Hz (40.02 s); its robot and SMPL references come from the matching official
`walk_forward_amateur_001__A001` sample. SMPL replay injects these matched fields
through an audit-only integrated-state adapter; the production integrated tool
still accepts G1 NPZ motion only. XY error compares final relative displacement
in each initial root frame, not body/joint tracking accuracy. Live PICO and real
robot stability still require device validation.

Commands, fixtures, metrics and trajectories are in local
`outputs/sonic_adaptation_audit/`. Repeat prepared integrated cases with:

```bash
env -u ALL_PROXY -u all_proxy \
  HF_HUB_OFFLINE=1 HF_HUB_DISABLE_TELEMETRY=1 SIM2REAL_ORT_NUM_THREADS=1 \
  uv run --no-sync python outputs/sonic_adaptation_audit/run_integrated.py --case smpl_walk
```

Other cases: `smpl_neutral`, `g1_walk`. The environment removals avoid this
machine's unsupported `socks://` proxy URL during cached asset resolution.
